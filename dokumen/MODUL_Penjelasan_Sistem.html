1. Pendahuluan & Tujuan

Sistem ini adalah dashboard web lokal yang memantau kondisi beberapa server/laptop dari satu laptop pusat, secara terus-menerus dan aman.

Di lingkungan pabrik LNG, server-server penting (mis. historian, database, aplikasi proses seperti Exaquantum) harus selalu sehat. Kalau CPU/RAM/disk penuh atau sebuah layanan mati, dampaknya bisa serius. Tujuan sistem ini:

  • Memantau CPU, RAM, Disk, dan Jaringan tiap server secara real-time.
  • Mendeteksi masalah lebih awal — server mati, layanan kritis berhenti, atau aplikasi berisiko terpasang.
  • Menyimpan riwayat ke database Oracle untuk analisa tren & laporan keandalan (% uptime).
  • Menghasilkan laporan (Excel & PDF) untuk dokumentasi ke pembimbing/atasan.

Semua ini dilakukan tanpa memasang aplikasi apa pun di server yang dipantau, dan tanpa mengubah apa pun di dalamnya.

2. Prinsip Non-Interference

Non-Interference artinya "tidak mengganggu". Ini aturan utama sistem: pemantauan hanya boleh MEMBACA angka, tidak boleh menulis, mengubah, atau membebani server yang dipantau.

Kenapa penting? Server pabrik menjalankan proses kritis. Alat pantau tidak boleh menjadi sumber masalah baru. Karena itu sistem ini hanya membaca (read-only), memakai cache agar ringan, dan tidak memasang service berat di server target.
  • Agen hanya membaca angka resource lalu menyajikannya sebagai teks (JSON) — tidak menyentuh data/proses.
  • Hasil bacaan di-cache 2 detik di agen, jadi walau banyak yang mengakses, beban server tetap kecil.
  • Dashboard hanya menarik/membaca dari agen; tidak pernah mengirim perintah yang mengubah server.

3. Gambaran Umum Sistem

Bayangkan seperti ruang kontrol (control room) mini untuk IT: di satu layar, operator bisa melihat kondisi semua server sekaligus — mana yang sehat (hijau), mana yang perlu dicek (kuning/merah), dan menggali detail tiap server bila perlu.

Sistem terdiri dari 3 bagian yang bekerja sama:

  1. Agen — program kecil (PowerShell) di tiap server target, yang "melapor" kondisi resource.
  2. Dashboard (server pusat) — program Python di laptop pusat yang mengumpulkan data, menyimpannya ke Oracle, dan menyajikan halaman web.
  3. Browser — tampilan yang dilihat pengguna (kartu server, grafik, laporan).

4. Arsitektur (3 Lapis)

🖥️ Lapis 1 — Agen di Server Target (port 9091, PowerShell, TANPA install)
Membaca CPU/RAM/Disk/Jaringan, daftar aplikasi terpasang, serta status service & port kritis. Otomatis mendaftarkan diri ke dashboard. Menyajikan endpoint: / metrik, /apps, /check, /top.
⬇ lapor data (dibaca dashboard)
🧠 Lapis 2 — Dashboard Server (port 9090, Python)
Mengumpulkan data dari semua agen, menyimpan ke Oracle tiap 10 detik, memantau layanan kritis & keamanan lewat 5 worker latar, membuat laporan Excel/PDF, dan menyajikan halaman web + API.
⬇ sajikan web + API
🌐 Lapis 3 — Browser (Tampilan)
Halaman dashboard bergaya modern (glassmorphism, mode gelap, animasi). Menampilkan kartu tiap server, detail metrik + grafik, riwayat & % uptime, dan tombol laporan.
Analogi: Agen = perawat yang mencatat tanda vital tiap pasien. Dashboard = ruang jaga yang mengumpulkan semua catatan & menyimpannya. Browser = monitor di ruang jaga yang dilihat dokter.

5. Cara Kerja / Alur Data

  1. Agen dijalankan di server target → otomatis mendaftar ke dashboard (kirim nama & IP).
  2. Agen membaca resource (CPU/RAM/Disk/Net) dan menyimpannya di cache 2 detik.
  3. Dashboard menarik data dari tiap agen, sekaligus cek ONLINE/OFFLINE + latensi.
  4. Tiap 10 detik, dashboard menyimpan metrik ke Oracle (tabel server_monitoring).
  5. Worker latar berkala: memindai aplikasi (tiap 5 menit) & layanan/port kritis (tiap 60 detik); mencatat ke Oracle bila ada temuan/perubahan.
  6. Browser menampilkan semuanya, memuat grafik riwayat dari Oracle, dan bisa mengunduh laporan.

7. Daftar Fitur

📊 Monitoring resource

CPU, RAM, Disk, Jaringan tiap server; status ONLINE/OFFLINE + latensi.

🏷️ Nama panggilan (label)

Beri nama mudah tiap server (mis. "Laptop Pak Erwan") tanpa mengubah hostname.

🛡️ Deteksi aplikasi

Menandai server yang memasang aplikasi berisiko (remote access, torrent, dll).

⚙️ Layanan & port kritis

Memastikan Exaquantum/SQL/historian & port pentingnya tetap hidup; alarm bila mati.

🔎 Top proses (RAM/CPU)

Melihat aplikasi paling berat di server — seperti Task Manager jarak jauh.

📈 Riwayat, tren & % uptime

Grafik CPU/RAM/Disk per rentang waktu, persentase uptime, dan daftar downtime.

💽 Prediksi disk penuh

Memperkirakan kapan disk akan penuh berdasarkan tren pemakaian.

📑 Laporan Excel & PDF

Laporan keseluruhan atau per-server (ringkasan, riwayat, deteksi, uptime).

⚙️ Ambang batas & retensi

Batas aman bisa diatur di UI; data lama otomatis dibersihkan agar DB tak membengkak.

🎨 UI modern

Glassmorphism, mode gelap, animasi halus, splash pembuka berlogo Badak LNG.

9. Cara Menjalankan & Deploy

Di laptop pusat (dashboard)

Jalankan server dashboard, lalu buka browser:

python dashboard_server.py → buka http://localhost:9090

Di server/laptop yang mau dipantau (agen)

Cukup satu perintah di PowerShell server itu (alamat dashboard otomatis terisi):

irm http://<IP-dashboard>:9090/setup | iex  (jalankan agen)

irm http://<IP-dashboard>:9090/setup-service | iex  (pasang sebagai service auto-start, untuk server 24 jam)

Catatan: membuka firewall port 9091 butuh hak Administrator (perintah di atas otomatis meminta izin). Firewall cukup dibuka sekali per server.

10. Manfaat untuk Pabrik

  • Deteksi dini — tahu server bermasalah sebelum berdampak ke proses produksi.
  • Bukti keandalan — angka % uptime & catatan downtime untuk laporan resmi.
  • Keamanan — mengetahui aplikasi berisiko yang terpasang di server.
  • Aman & ringan — read-only, tanpa install, tidak mengganggu server (Non-Interference).
  • Hemat & fleksibel — berbasis alat yang sudah ada (PowerShell, Python, Oracle), mudah dikembangkan.
